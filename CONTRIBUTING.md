# Contributing to Beforepull

Thanks for contributing. Open an issue describing the problem and a minimal reproduction before proposing major features.

- Keep changes narrow and explain the failure they address.
- Add regression tests for every reported bug.
- Avoid dependencies unless they materially improve correctness.
- Do not commit passwords, private endpoints, access tokens or real user data.
- Document any behavior and security-boundary changes in the README.
- Run the entire test suite before requesting review.

Pull requests should include: purpose, sample input, expected output, test results and a brief risk assessment.
